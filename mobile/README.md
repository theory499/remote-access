# Proxia mobile clients

Two platform implementations of the Proxia client. Both apps
configure Firebase **at runtime** from a QR code generated by the
desktop host's setup wizard — they do not ship with hardcoded Firebase
credentials.

| Folder | Platform | Stack |
| --- | --- | --- |
| `android/` | Android 7.0+ | Kotlin, AndroidX, CameraX + ML Kit Barcode Scanning, Firebase Auth / Database, webrtc-sdk |
| `ios/`     | iOS 15+    | SwiftUI, AVFoundation, FirebaseAuth / FirebaseDatabase, WebRTC-SDK pod |

See each subfolder's own README for build and run instructions:

- [`android/README.md`](android/README.md) (mostly the existing build
  flow with `gradle` + `./gradlew`).
- [`ios/README.md`](ios/README.md) (XcodeGen + CocoaPods).

## Why no config files in the repo?

The previous design required the user to drop a
`google-services.json` (Android) or `GoogleService-Info.plist` (iOS)
into the source tree before building. That created two problems:

1. The build broke for anyone who cloned the repo without going through
   Firebase setup first.
2. Credentials had to be checked in or shared out of band, which is
   easy to get wrong.

Both apps now use Firebase's runtime `FirebaseOptions` API
(`FirebaseApp.initializeApp(context, options)` on Android,
`FirebaseApp.configure(options:)` on iOS). The credentials arrive over
the network — specifically, encoded in a QR code displayed by the
desktop wizard — and are persisted locally in the app's private
preferences (Android `SharedPreferences`, iOS `UserDefaults`).
