# Glossary

Definitions for every domain-specific term used in the source code
and the documentation, in alphabetical order.

| Term | Meaning |
| --- | --- |
| **Anonymous authentication** | A Firebase sign-in mode that gives every user a stable UID without requiring credentials. Both peers use it so the database rules can pin UIDs to roles. |
| **AVPF** | "Audio-Visual Profile with Feedback", the RTP profile WebRTC uses; it permits the receiver to send rapid feedback (NACK, PLI) to the sender. |
| **Bundling (esbuild)** | The process of combining ES modules into a single file so the renderer can load Firebase from `node_modules`. Run with `npm run build:renderer`. |
| **Client** | The Android phone in this suite - the side that watches the desktop and sends input. Synonymous with the peer role `"client"` in Firebase. |
| **Coalescing (mousemove)** | The renderer-side optimisation that keeps only the latest `mousemove` message per frame to avoid flooding `nut.js` with cursor updates. |
| **contextBridge** | An Electron API that exposes a small typed surface from preload into the renderer while keeping `contextIsolation` enabled. Used to expose `window.api`. |
| **Data channel** | A bidirectional, reliable, ordered message stream provided by WebRTC. This suite uses one channel named `input` for protocol messages. |
| **`desktopCapturer`** | The Electron API used by the host to enumerate capturable screens / windows. Lives in the main process. |
| **DTLS-SRTP** | Datagram Transport Layer Security combined with Secure Real-time Transport Protocol; the encryption WebRTC uses for media. |
| **`EglBase`** | An OpenGL ES context wrapper from the Android WebRTC library. Required to drive the `SurfaceViewRenderer`. |
| **Encoder** | (1) Hardware video encoder used by the sender. (2) `InputEventEncoder`, the Kotlin object that produces protocol JSON. |
| **ESM / CJS** | EcmaScript Modules vs. CommonJS. The desktop's shared modules are CJS so they work in both Node and the esbuild-bundled renderer. |
| **`@nut-tree-fork/nut-js`** | The cross-platform native input simulation library used by the desktop. A maintained fork of `nut.js`. |
| **Host** | The desktop computer being controlled - the side that captures and shares its screen. Synonymous with the peer role `"host"` in Firebase. |
| **ICE candidate** | A possible network endpoint (host, server-reflexive, or relayed) for WebRTC to try. The two peers exchange candidates through Firebase until they find a working pair. |
| **`InputController`** | Desktop module responsible for translating protocol messages into OS-level mouse and keyboard events. |
| **`InputEventEncoder`** | Mobile object responsible for producing protocol JSON for each user gesture or keystroke. |
| **JNI** | Java Native Interface, used internally by the Android WebRTC library to bridge to the C++ implementation. Not directly invoked by this code. |
| **Pairing code** | The six-character string that uniquely identifies a session. Generated by the desktop, typed by the user on the phone. See `session-id.js`. |
| **Peer** | Either side of a WebRTC connection. In this suite, "peer" usually disambiguates host from client. |
| **`PeerConnection` / `RTCPeerConnection`** | The core WebRTC object that owns the encrypted transport, the SDP descriptions, and the ICE machinery. Each session has one per peer. |
| **Presence** | The `host` or `client` node inside `sessions/{code}` that confirms a peer is online. Removed automatically via `onDisconnect`. |
| **Preload** | An Electron script that runs once per renderer with privileged access. Used here to expose the typed `window.api` bridge. |
| **Protocol** | The application-level JSON message format documented in [PROTOCOL.md](PROTOCOL.md). Distinct from the lower-level WebRTC transport. |
| **Realtime Database** | Firebase's NoSQL realtime tree database. Used as the signalling channel between the two peers. |
| **Renderer** | The Electron renderer process. Hosts the UI, Firebase, and WebRTC code. |
| **`requestAnimationFrame`** | A browser API that schedules work for the next display frame. Used to drain pending `mousemove` events at 60 Hz. |
| **Restart** | The desktop UI action that tears down the current session and starts a new one with a fresh pairing code. |
| **Role** | Either `"host"` or `"client"`. Encoded in the Firebase rules so the two peers cannot impersonate each other. |
| **SDP** | Session Description Protocol; the text format that conveys WebRTC capabilities (codecs, IP addresses, media descriptions) between peers. |
| **Session** | The lifetime of one pairing between a host and a client, identified by a pairing code. |
| **`SessionController`** | Desktop module that owns the pairing-code lifecycle and the disconnect grace timer. |
| **Signalling** | The process of getting two WebRTC peers to agree on connection parameters. In this suite, signalling is mediated by Firebase Realtime Database. |
| **`SignalingClient`** | Both desktop and Android have one. Wraps the Realtime Database operations needed for signalling. |
| **`SurfaceViewRenderer`** | An Android WebRTC View that decodes and renders an incoming `VideoTrack`. |
| **STUN** | Session Traversal Utilities for NAT. A protocol that lets peers learn their public IP. Free public STUN servers (Google) are used by default. |
| **TURN** | A relay-based fallback when peers cannot connect directly. Not configured by default. |
| **UID** | The unique identifier Firebase assigns to each authenticated user (anonymous users included). Used by the rules to bind a participant to a role. |
| **WebRTC** | The browser standard for peer-to-peer media and data. Used here for both the video track and the input data channel. |
