# Desktop module reference

A file-by-file tour of the desktop Electron host. Each section names
its file path, the process it runs in, the dependencies it pulls in,
the public surface it exposes, and the callers that use it.

## Directory map

```
desktop/
├── package.json            npm metadata and build scripts
├── jest.config.js          test runner configuration
├── .eslintrc.json          lint configuration
├── .gitignore              build artifacts and credentials
└── src/
    ├── main/               Electron main process modules
    │   ├── main.js
    │   ├── input-controller.js
    │   ├── firebase-signaling.js
    │   ├── screen-capture.js
    │   └── session-controller.js
    ├── preload/
    │   └── preload.js      contextBridge between renderer and main
    ├── renderer/           runs in the Electron renderer process
    │   ├── index.html
    │   ├── styles.css
    │   ├── renderer.js     pre-bundle source (ESM)
    │   └── renderer.bundle.js  generated by esbuild; gitignored
    └── shared/             code reused by both processes
        ├── protocol.js
        ├── session-id.js
        └── firebase-config.js  (user-supplied credentials)
```

The renderer is bundled with esbuild because the Firebase modular SDK
ships only ESM modules from `node_modules`. The bundle is regenerated
by `npm run build:renderer` and inlined as `<script src="renderer.bundle.js">`.

## src/main/main.js

**Process:** Electron main.

**Responsibility:** Application entry point. Owns the `BrowserWindow`,
the `InputController` singleton, and the IPC handlers exposed to the
renderer.

**Imports:**
- `electron` (`app`, `BrowserWindow`, `ipcMain`).
- `./input-controller` for OS-level input simulation.
- `./screen-capture` for source enumeration.
- `../shared/protocol` for `validate`.

**Public surface:**
- IPC channel `screen:list-sources` returns `[{ id, name, display_id }]`.
- IPC channel `input:event` accepts a protocol message and forwards it
  to the controller. Returns `{ ok: true }` or `{ ok: false, error }`.
- IPC channel `input:screen-size` returns `{ width, height }` once the
  controller has queried the OS once.

**Lifecycle:**
1. `app.whenReady()` resolves.
2. `registerIpcHandlers()` runs.
3. `createWindow()` builds the renderer window with
   `contextIsolation: true`, `nodeIntegration: false`, and the preload
   script attached.
4. On `window-all-closed`, the app quits on every platform except
   macOS, matching standard Electron behaviour.

## src/main/input-controller.js

**Process:** Electron main.

**Responsibility:** Translate validated protocol messages into OS-level
mouse and keyboard actions via `@nut-tree-fork/nut-js`.

**Class:** `InputController`

**Constructor options:**
- `nut` (default: `require('@nut-tree-fork/nut-js')`) - the input
  backend. Tests inject a mock.
- `screenSize` - optional pre-known screen dimensions. If omitted, the
  controller queries `nut.screen.{width,height}()` on first use and
  caches the result.
- `keyMap` / `modifierMap` / `buttonMap` - optional overrides used in
  tests. Production code falls back to internal maps built from
  `nut.Key` and `nut.Button`.

**Public methods:**

| Method | Purpose |
| --- | --- |
| `handle(event)` | The dispatch entry point. Switches on `event.type` and calls one of the methods below. Throws on unknown types. |
| `mouseMove(xNorm, yNorm)` | Converts to pixels and calls `nut.mouse.setPosition(...)` (falling back to `move(straightTo(...))` if needed). |
| `mouseDown(button)` / `mouseUp(button)` | `nut.mouse.pressButton` / `releaseButton` with the resolved button enum. |
| `click(xNorm, yNorm, button)` | Moves then calls `nut.mouse.click(button)`. |
| `scroll(dx, dy)` | Picks one of `scrollUp`, `scrollDown`, `scrollLeft`, `scrollRight` depending on sign. |
| `keyDown(key, modifiers)` | Presses each not-yet-pressed modifier, then the key. Tracks state in `_heldModifiers` / `_heldKeys`. |
| `keyUp(key)` | Releases the key. Releases all held modifiers only when no other regular keys are held. |
| `type(text)` | `nut.keyboard.type(text)` - whole-string text injection. |
| `ensureScreenSize()` | Queries `nut.screen` once and caches the result. |

**Why modifier tracking matters:** see
[INPUT_HANDLING.md](INPUT_HANDLING.md#3-discrete-key-presses).

**Threading:** every method is `async`. Calls are serialised by the
renderer's `attachDataChannel` mousemove coalescer, so the controller
never sees overlapping `handle` calls in practice.

## src/main/firebase-signaling.js

**Process:** Either - the class is process-agnostic. The renderer is
the actual caller in the production wiring.

**Responsibility:** A thin wrapper around the Firebase Realtime
Database that exposes only the operations needed by signalling.

**Class:** `FirebaseSignaling`

**Constructor parameters:**
- `database` - Firebase database handle.
- `role` - either `'host'` or `'client'`.
- `sessionCode` - the six-character session code.
- `uid` - the authenticated user id.
- `refFactory(db, path)` - builds a `DatabaseReference` for the given
  path. Production passes `firebase/database`'s `ref`. Tests pass a
  fake.
- `serverValue` - object with a `TIMESTAMP` property used in
  `registerPresence`.
- `helpers` - a record of `{ set, push, remove, onValue, onChildAdded,
  onDisconnectRemove }`. The renderer builds these from
  `firebase/database`; tests pass an in-memory implementation from
  `tests/integration/fake-firebase.js`.

**Public methods:**

| Method | Effect |
| --- | --- |
| `registerPresence()` | Writes `{ uid, createdAt }` to `sessions/{code}/{role}` and arms `onDisconnect().remove()`. |
| `watchPeerPresence(cb)` | Subscribes to the peer's role node; `cb(presence)` fires with the value or `null`. |
| `sendOffer(desc)` | Writes `{ type, sdp }` to `sessions/{code}/offer`. |
| `watchOffer(cb)` | Subscribes to `sessions/{code}/offer`. |
| `sendAnswer(desc)` | Writes to `sessions/{code}/answer`. |
| `watchAnswer(cb)` | Subscribes to `sessions/{code}/answer`. |
| `sendIceCandidate(c)` | Pushes a new child under `sessions/{code}/iceCandidates/{role}`. |
| `watchIceCandidates(cb)` | Subscribes to `sessions/{code}/iceCandidates/{peerRole}`, firing once per child. |
| `clearSession()` | Removes the whole `sessions/{code}` subtree. |
| `dispose()` | Removes every listener registered through the helpers. Idempotent. |

**Why the helpers indirection?** The Firebase modular SDK does not
expose a stable interface that is easy to mock. Wrapping the half-dozen
calls we use in a `helpers` record lets us pass an in-memory
implementation in tests without monkey-patching globals.

## src/main/screen-capture.js

**Process:** Electron main.

**Responsibility:** Enumerate desktop capture sources via Electron's
`desktopCapturer`.

**Public functions:**
- `listScreenSources(types = ['screen'])` returns
  `[{ id, name, display_id }]`. The renderer uses the `id` as the
  `chromeMediaSourceId` constraint for `getUserMedia`.
- `selectPrimaryScreen()` returns the first source or throws if none
  are available.

The whole module is fewer than 25 lines; the heavy lifting is in
Electron's native bindings.

## src/main/session-controller.js

**Process:** Renderer (it is imported by the bundled renderer code, not
by `main.js` - the name is historic).

**Responsibility:** Coordinate `FirebaseSignaling` and high-level
session state (pairing code generation, status updates, disconnect
grace period).

**Class:** `SessionController`

**Constructor parameters:**
- `signalingFactory({ role, uid, sessionCode })` - builds a configured
  `FirebaseSignaling`.
- `onStatus({ status, code })` - status callback.
- `onLog(message)` - log callback.

**Public methods:**
- `start({ uid })` - generates a code, registers presence, subscribes
  to peer presence, emits `{ status: 'waiting', code }`. Returns
  `{ sessionCode }`.
- `stop()` - clears the session in Firebase, disposes the signaling
  client, emits `{ status: 'stopped' }`.

**Disconnect grace period:** when the peer presence disappears, the
controller starts a `PEER_DISCONNECT_GRACE_MS` (10 second) timer and
transitions to `waiting` if the peer has not returned by then. This
absorbs brief network blips that would otherwise drop the session.

## src/preload/preload.js

**Process:** Preload (runs once per renderer, with access to both Node
and the DOM).

**Responsibility:** Expose a typed API to the renderer via
`contextBridge.exposeInMainWorld`.

```js
contextBridge.exposeInMainWorld('api', {
  listScreenSources: () => ipcRenderer.invoke('screen:list-sources'),
  dispatchInputEvent: (m) => ipcRenderer.invoke('input:event', m),
  getScreenSize: () => ipcRenderer.invoke('input:screen-size')
});
```

This is the only bridge between the renderer (where Firebase and
WebRTC live) and the main process (where `desktopCapturer` and `nut.js`
live). Nothing else crosses the boundary.

## src/renderer/renderer.js

**Process:** Renderer.

**Responsibility:** The session orchestrator. Initialises Firebase,
authenticates, creates a session via `SessionController`, owns the
`RTCPeerConnection`, attaches the `MediaStream` and the input
`RTCDataChannel`, exchanges ICE candidates, and routes incoming
messages back to the main process.

**Top-level constants:**
- `ICE_SERVERS` - the STUN configuration. The default is Google's
  public STUN servers. To add a TURN server, push an additional entry
  here.
- `STATUS_LABELS` - human-readable status strings.

**Module state (module-level lets):**
- `firebaseApp`, `auth`, `database` - Firebase handles.
- `peerConnection` - the current `RTCPeerConnection` or `null`.
- `dataChannel` - the current input data channel.
- `localStream` - the captured screen `MediaStream`.
- `session` - the current `SessionController`.
- `pingId`, `pingTimer`, `pendingPings` - latency tracking.
- `isNegotiating` - guard against duplicate `negotiate()` calls.

**Key functions:**

| Function | Role |
| --- | --- |
| `bootstrap()` | Top-level entry. Initialises Firebase, signs in, starts the first session. |
| `startSession()` | Constructs a new `SessionController` and registers the renegotiation trigger. |
| `negotiate()` | Captures the screen, builds the peer connection, creates the offer, publishes it, subscribes to the answer and ICE candidates. Guards against double-execution. |
| `attachDataChannel(channel)` | Wires up `onopen`, `onclose`, `onmessage`. Implements the mousemove coalescer described in [INPUT_HANDLING.md](INPUT_HANDLING.md). |
| `schedulePing()` | Sends a `ping` and re-arms itself every 2 seconds. Cancelled and re-armed atomically. |
| `restart()` | Tears down everything (data channel, peer connection, media tracks, signaling) and starts fresh with a new pairing code. |

## src/renderer/index.html

The renderer markup. Sets a strict Content Security Policy that allows
only:

- Same-origin script and styles.
- HTTPS / WSS to `*.firebaseio.com` and `*.googleapis.com`.

The CSP is what makes `nodeIntegration: false` safe in this context -
even if a renderer bug allowed remote script injection, it could not
load arbitrary code from a third-party origin.

The HTML contains the three cards shown in the UI:
1. Pairing code card.
2. Connection metrics card (WebRTC state, ICE state, RTT).
3. Restart button.
4. A scrollable log.

## src/shared/protocol.js

**Process:** Both.

**Responsibility:** Single source of truth for the wire protocol. The
desktop validates everything that arrives over the data channel
against the same schema the Android `InputEventEncoder` is built
against.

See [PROTOCOL.md](PROTOCOL.md) for the schema. The implementation
exports:

| Export | Purpose |
| --- | --- |
| `validate(message)` | Returns `true` if `message` matches the schema. |
| `parse(line)` | Parses a UTF-8 JSON line and returns the validated object, or `null` if either step fails. |
| `encode(message)` | Validates then returns the JSON string. Throws if invalid. |
| `BUTTONS`, `MODIFIERS`, `KEYS`, `TYPE_TEXT_MAX_LENGTH` | The constants the validator uses. |

---

## src/shared/session-id.js

**Process:** Both (Node 19+ has the same Web Crypto API as browsers).

**Responsibility:** Generate and validate six-character pairing codes.

**Alphabet:** `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (32 characters). The
ambiguous glyphs `0/O` and `1/I` are excluded so users do not mistype
them.

**Entropy:** 32^6 = 1,073,741,824 distinct codes (~30 bits). For a
six-character pairing code used for the lifetime of a session, this
is comfortably resistant to online guessing - particularly because
the Firebase rules also bind UIDs to the original participants once
they have written their presence (see
[SECURITY.md](SECURITY.md)).

**Public functions:**
- `generate()` returns a six-character code.
- `isValid(code)` returns `true` if the code matches the regex
  `^[ABCDEFGHJKLMNPQRSTUVWXYZ23456789]{6}$`.

## Build pipeline

```
npm install        # one-time
npm run build:renderer   # esbuild bundles renderer.js -> renderer.bundle.js
npm start          # invokes build:renderer, then electron .
```

`electron-builder` is configured under the `build` section of
`package.json` to produce DMG (macOS), NSIS installer (Windows), and
AppImage (Linux) artifacts via `npm run package`.

## Tests

| File | Layer | What it covers |
| --- | --- | --- |
| `tests/unit/protocol.test.js` | Unit | Schema validation, parsing, encoding, cross-platform shape compatibility. |
| `tests/unit/session-id.test.js` | Unit | Code length, alphabet, entropy across 1000 samples. |
| `tests/unit/input-controller.test.js` | Unit | Every method of `InputController`, mocked against `tests/mocks/nut-js.js`. |
| `tests/unit/screen-capture.test.js` | Unit | Source enumeration and error paths. |
| `tests/integration/signalling.test.js` | Integration | Two `FirebaseSignaling` instances exchanging offer / answer / ICE candidates over `tests/integration/fake-firebase.js`. |
| `tests/integration/session-controller.test.js` | Integration | `SessionController` start / peer-present / peer-disconnect transitions. |

Mocks live under `tests/mocks/` and are wired through `jest.config.js`'s
`moduleNameMapper`. The fake Firebase database in
`tests/integration/fake-firebase.js` implements just enough of the
Realtime Database API to drive the signalling client end-to-end.

Run everything with `npm test`. See [TESTING.md](TESTING.md) for more.
